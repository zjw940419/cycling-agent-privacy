Personal Cycling Agent

Privacy Policy

How the local cycling training application processes and stores information.

Effective date: 14 November 2026

Operator: zjw940419

Contact: GitHub Issues

Purpose

Personal Cycling Agent is a personal cycling training tool that runs on the user's computer. It uses authorized training and recovery information to produce training drafts and retrospective reports. It is not affiliated with WHOOP or Intervals.icu.

Information processed

With authorization, the application requests sleep and recovery records from WHOOP. Its stored daily summaries include sleep duration, recovery score, heart rate variability, resting heart rate, and associated dates. Other fields included in the WHOOP sleep and recovery API responses are processed in memory while extracting these summaries.

The application also retrieves activity records, wellness records, and calendar events returned by the Intervals.icu API. These responses may contain additional fields supplied by that service and are saved as local snapshots. Users may enter their training goals, availability, FTP, equipment details, weight, and daily fatigue, soreness, or illness feedback.

API credentials and OAuth access and refresh tokens are stored locally to enable authorized access. WHOOP passwords are entered on WHOOP's authentication pages, not collected by this application.

Use and disclosure

Information is used for personal training analysis, recovery checks, training drafts, and reports. When the user explicitly runs the calendar publishing command, planned workouts and their descriptions are sent to Intervals.icu. Descriptions may include recovery-related explanations derived from the user's data. Their visibility then depends on the user's Intervals.icu account and sharing settings.

The current application does not sell data, include advertising or analytics SDKs, or send records to a language-model service. It communicates with WHOOP and Intervals.icu for the requested integrations. Those services process requests under their own policies. User-managed backups, file synchronization, and sharing tools operate independently of this application.

Storage and retention

Credentials, tokens, snapshots, subjective feedback, plans, reports, and synchronization records are stored in local files. Sensitive files created by the application use owner-only file permissions. These permissions do not constitute application-level encryption.

Files remain until the user deletes them; the current version does not automatically expire historical snapshots or reports. Default storage locations are the project's data and output directories, but users may configure other locations.

Control and deletion

Users can stop running the application at any time and remove local credentials, tokens, and stored records. To disable further access, they can revoke the WHOOP integration through WHOOP's available account controls or support, and revoke or regenerate their Intervals.icu API key. Deleting local token files alone does not revoke tokens at the provider.

Removing local files does not remove existing records or published workouts from WHOOP or Intervals.icu, nor copies in user-managed backups. Those copies must be managed separately in the relevant service or backup system.

Changes and contact

This policy must be updated before introducing materially different processing, such as cloud hosting, language-model analysis, or service for other users. Questions about this application or its data handling can be sent to the operator using the GitHub Issues link above. This issue tracker is public; do not include health records, passwords, or API credentials.

This policy describes the current local command-line application. It is not a WHOOP or Intervals.icu policy.
